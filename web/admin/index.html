Member Calendar

Share the calendar with

Connect a calendar
  1. Open Google Calendar on a computer, signed in to the account that owns the club calendar.
  2. In the left column, point at the calendar, click the three dots, then Settings and sharing.
  3. Under Share with specific people or groups, click Add people and groups, paste the address shown above, choose Make changes to events, and click Send.
  4. Scroll down to Integrate calendar and copy the Calendar ID.
  5. Paste it into Calendar ID on this page, tick Post live events to this calendar, and click Save.
  6. Within 5 minutes the status at the top of this section turns green and live events appear on the calendar.
New school year: switch to a new calendar
  1. Make the new calendar in Google Calendar (for example, Member Calendar 2027-2028) and make it public the way the old one was.
  2. Share it with the address above, exactly as in Connect a calendar.
  3. Paste the new Calendar ID here and click Save.

What happens: upcoming events move to the new calendar within 5 minutes. Events that already happened stay on the old calendar as that year's record. Nothing needs to change on the server.

What gets posted, and when
  • An event is posted when it goes live on the events page: when an officer publishes it, or at the Monday 8:00 AM drop.
  • Edits (time, place, title, description) show up on the calendar within 5 minutes.
  • Unpublishing or deleting an event takes it off the calendar.
  • Each calendar event has the time, location, description, attire and a link to sign up. Paid-member events say Members only in the title.
  • Do not edit these events in Google Calendar directly. The next change on this site overwrites them. Change the event here instead.
  • Turning off Post live events stops posting. Events already on the calendar stay there.
One-time server setup (for whoever maintains the site)

Only needed once, or if the service account key is ever lost or rotated. The share address above comes from this key.

  1. In Google Cloud Console, create (or reuse) a project, enable the Google Calendar API, and create a service account. No roles are needed.
  2. On the service account, open Keys, add a JSON key, and download it.
  3. In a terminal in this repository: supabase secrets set GOOGLE_SERVICE_ACCOUNT_JSON="$(cat key.json)", then delete the downloaded file.
  4. Deploy the function: supabase functions deploy sync-calendar.
  5. Schedule it every 5 minutes with the SQL in docs/10-google-calendar.md.

Sign-up emails

How sign-up emails work
  • Each event's sign-up form sets when its confirmation email goes out (days before, and the time). Emails go out within 5 minutes of that time.
  • Paid members are emailed at the address on the roster, never one they type. Guests are emailed at the address they enter.
  • People who do not confirm in time are dropped, and the waitlist moves up.
  • Emails are sent through Resend from the address shown above. The Resend account belongs to the club email (pdsa.ucf@gmail.com), so it passes to the next board with that inbox.
One-time server setup (for whoever maintains the site)
  1. Sign up at resend.com with pdsa.ucf@gmail.com, add the domain pdsaucf.com, and add the DNS records Resend lists wherever pdsaucf.com is managed.
  2. Create an API key in Resend.
  3. In a terminal in this repository: supabase secrets set RESEND_API_KEY=re_... SIGNUP_EMAIL_FROM="PDSA UCF <events@pdsaucf.com>"
  4. Deploy the function: supabase functions deploy send-signup-emails.
  5. Schedule it every 5 minutes with the SQL in docs/09-event-signups.md.
